# 领域元认知档案冷启动

把一个领域的元认知档案从零落成并注入领域仓：创始人一句话 → 岔路问答 → 指认归格 → 冷启动稿件 → 注入 → 删源。

## 流程

1. **给定**：领域一句话目标由创始人给定，AI 不代配、不外推市场想象与演化路径——两次都在这里翻过车。目标句原话入档，不改写。
2. **先看真身**：进领域的仓与数据现场再动笔（支持域的真身是工单习惯，智能体域的真身是 337 段 session 与现成的 loops/skills 组织）。已有资产写进「别重复建设」，不另起炉灶。
3. **岔路问答**：一个一个问，只问正面陈述看不出分歧的岔路情形（「答得很好但没整理，算办完吗」「两版都能用留哪版」）。对不上改文档不改人。判据落死之前一律标「待岔路问答」，不许先填。
4. **指认归格**：二十类资产格子。两段分工——记录段落 journal（只增不改、缺档即建），加工整理段落 profile（快照替换、旧版退位）；未来三格对账——intention 是创始人给定的验收标尺（不由路线图推导、不由洞察支撑），insight 可错、每条带证伪条件、不被意图收买，roadmap 一格一验收、顺序由洞察撑着；brochure 是对外口径，保密边界先立、售卖口径占位；子系统不自建容器，存储、版本、正本、判据都借范畴。
5. **写冷启动稿件**：落 `data/profile/{domain}/`——`index.md`（总览：目标原话、核心循环、与范例域的对照表、待定判据、任务单元、已有资产、边界）＋各格 md（journal/profile/intention/insight/roadmap/brochure，每份写「本仓收什么、落位与写法、规矩、任务单元」，任务单元表带执行者 human/agent 与判据）。
6. **注入领域仓**：领域仓 AGENTS 认知段按修正过的模型改写——与模型直接冲突的段落整段替换（支持域的「AI 先应答、蒸馏回资产」循环、智能体域的空认知段），不冲突的（领域边界、工程纪律、子模块纪律）原样留；各资产仓 AGENTS 收录，**有存量 AGENTS 的合并不覆盖**（智能体域的 profile、roadmap 都有存量规矩，只加角色段）。分层提交：子仓推完 → 领域仓 AGENTS＋CHANGELOG＋指针推完。
7. **删源**：收录核对无误后，staging 稿件源侧删除不留副本——两处并存就是两个真源，未来 AI 分不清哪份新。留痕靠 CHANGELOG 与 git 历史。不属于搬运的既有档案（如 `pi-to-hermes.md`）保留。

## 判据落死的先例（引用，不重新发明）

- **客户支持**：办完 ⇔ 有经客户确认的工作日志；解决方案带适用条件，旧版退位；超时、不回、转出是正常结局。
- **智能体**：修正没有终态——落地＝假设入档，不再偏＝暂时在位，再现偏离＝怀疑、证伪退位；同任务形态不事前定义，靠偏离描述比对指认；适用范围绑模式不绑目录。

## 陷阱

- 代配目标或外推——用户一句话目标的字面最简理解就是答案。
- 判据没落死就先填——待定标着，等岔路问答。
- 覆盖存量 AGENTS——先读，后合，只加角色与判据。
- 注入后源侧留副本。
- 把「占位」当未完成项让未来 AI 去补——占位是声明。

## 验收

- 领域仓 AGENTS 认知段只有一个模型，无新旧并存；
- 各资产仓 AGENTS 就位，存量规矩都在，指针分层推完；
- staging 源侧只剩不属于搬运的文件；
- 每条判据要么落死带出处，要么标「待岔路问答」。
